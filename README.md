# pdf-compress

**智能 PDF 压缩工具** —— 先找"假肉"，再压"真肉"。

很多 PDF 的体积大头根本不是内容，而是**看不见的垃圾**。这个工具会先把它们剥掉，然后才用最克制的方式压缩真正需要压缩的部分。

实测：一份 63 页的品牌手册从 **34.4 MB 压到 16.3 MB（-52.7%）**，文字 100% 保留、矢量图形零损失、肉眼几乎看不出差别。

---

## 它解决什么问题

大多数 PDF 压缩工具一上来就无脑降分辨率，把好好的文档压成一团糊。但真实情况往往是：

**一份从 Illustrator 导出的 PDF，35 MB 里有 12 MB 是 Illustrator 的私有数据。**

`/PieceInfo` → `/AIPDFPrivateData` 是 Adobe Illustrator 内嵌的图层还原信息，只在你以后用 AI 重新打开这个 PDF 时才用得到。查看、打印、发给客户、上传网站——**完全用不到它**，但它常常占掉 30%~50% 的体积。

所以这个工具的策略是：

| 步骤 | 做什么 | 代价 |
|---|---|---|
| 1 | 剥离 Illustrator 私有数据 | 失去在 AI 里还原图层的能力 |
| 2 | 只对**超过目标 DPI** 的图片重采样 | 高分辨率图变柔和 |
| 3 | 字体子集化 + 对象去重 + 流压缩 | 无 |

**文字和矢量图形从头到尾不会被碰。** 所以文字永远可选中、可搜索、可复制。

## 安装

```bash
pip install pymupdf
```

只需要 PyMuPDF 一个依赖，无其他第三方包。

## 快速开始

```bash
# 最常用：剥离 AI 数据 + 自动选档压到 20MB 以内
python pdf_compress.py input.pdf -s -t 20

# 默认 high 档（画质与体积平衡）
python pdf_compress.py input.pdf

# 批量处理，输出到目录
python pdf_compress.py *.pdf -o out/
```

输出默认是 `原名_compressed.pdf`，**不会覆盖原文件**。

## 参数

| 参数 | 说明 |
|---|---|
| `inputs` | 输入 PDF，支持多个（支持通配符） |
| `-o, --output` | 输出文件或目录，默认加 `_compressed` 后缀 |
| `-l, --level` | 压缩档位，默认 `high` |
| `-s, --strip-ai` | 剥离 Illustrator 私有数据 |
| `-t, --target MB` | 目标大小，自动选达标档位 |
| `--version` | 显示版本 |

### 档位

画质从高到低，体积从大到小：

| 档位 | 图片重采样策略 | 适用场景 |
|---|---|---|
| `ultra` | 仅处理 > 201 DPI 的图，降到 200 DPI，q72 | 要打印或给设计师看 |
| `high` | 仅处理 > 121 DPI 的图，降到 120 DPI，q75 | **推荐**，屏幕+打印都够用 |
| `balanced` | 仅处理 > 101 DPI 的图，降到 100 DPI，q80 | 体积更小，画质仍良好 |
| `strong` | 仅处理 > 101 DPI 的图，降到 100 DPI，q65 | 仅屏幕快速预览 |
| `lossless` | 不重压任何图片 | 只想清理垃圾，绝不接受画质变化 |

> 注意"仅处理 > N DPI"这个设计：**低于阈值的图片原封不动**。一份文档里显示尺寸很小的图往往已经是合理分辨率，再去重压它们纯属浪费画质。

### 自动选档（`-t`）

给定目标大小后，工具会**从画质最高的档位往下试**，选第一个达标的：

```bash
python pdf_compress.py brandbook.pdf -s -t 20
```

```
brandbook.pdf
  34.4 MB -> 16.3 MB  省 52.7%   [档位 high | 剥离 AI 数据 63 页]
  输出: brandbook_compressed.pdf
```

如果**只剥离 AI 数据就已经达标**，它一张图都不会碰——这是最理想的结果。

## 工作原理

### 1. 剥离 Illustrator 私有数据

Illustrator 导出的 PDF 里，每个页面都有一个 `/PieceInfo` 条目指向一份共享的私有数据字典，里面挂着上百个 `AIPDFPrivateDataN` 对象。这些对象是**无类型裸流**（只有 `/Length`，没有 `/Subtype`），所以普通的"清理未引用对象"根本清不掉它们——必须先把 `/PieceInfo` 这个入口断掉，它们才会变成真正的垃圾对象被回收。

### 2. 图片重采样

用 PyMuPDF 的 `rewrite_images()`，按 DPI 阈值筛选。它内部会正确处理 CMYK 色彩空间和 JPEG 重编码，比手写 PIL 流程可靠得多（手写容易踩 CMYK 反转的坑——PDF 里的 CMYK JPEG 常带 `/Decode [1 0 1 0 1 0 1 0]` 反转约定，搞错了整个文档颜色就废了）。

### 3. 收尾

- `subset_fonts()` —— 字体子集化，只保留实际用到的字形
- `save(garbage=4, deflate=True, clean=True, use_objstms=1)` —— 对象去重、流压缩、交叉引用表压缩

## 画质

我们不信"看起来差不多"这种说法，所以用客观指标验证。

测试样本：63 页品牌手册，1920×1080pt 页面，31 张 CMYK 图片。

| 指标 | 结果 |
|---|---|
| 体积 | 34.43 MB → **16.27 MB**（-52.7%） |
| 页数 | 63 → 63 |
| 页面尺寸 | 63 页全部一致 |
| **可提取文字** | 49371 字符 → **49371 字符（100%）**，逐页完全一致 |
| 字体引用 | 171 → 171 |
| PSNR（逐页渲染对比） | 最低 39.9 dB，均值 95.0 dB |
| SSIM | 均值 0.9994，最低 0.9343 |

作为参考：PSNR 35 dB 以上通常被认为"肉眼难以分辨"，40 dB 以上属于高保真。这份文档 63 页全部在 35 dB 以上。

想自己验证的话，思路是：用 PyMuPDF 把原文件和压缩文件逐页渲染成位图，逐像素算 PSNR/SSIM。

## 常见问题

**Q：压完之后文字还能搜索/复制吗？**
能。文字和矢量图形完全没被碰过，文字层 100% 保留。

**Q：`-s` 之后还能在 Illustrator 里编辑吗？**
不能还原图层了。**原文件请务必保留**——对外分发用压缩版，要改设计用原文件。

**Q：能处理扫描件吗？**
可以。扫描件整页都是图片，`-l strong` 通常能省 50%~90%。

**Q：文件是加密的怎么办？**
工具会跳过并提示，需要先用密码解除加密。

**Q：能压到指定大小吗？**
`-t 20` 会从画质最高的档位往下试，选第一个达标的。如果连 `strong` 档都超标，会用 `strong` 档并在输出里提示"未达目标"。

**Q：为什么我的文件压不动？**
可能原因：① 内容本来就是矢量图（比如纯文字或图表 PDF），本身已经很紧凑；② 图片已经优化过，没有超采样的图可降；③ 试试加 `-s` 剥离 AI 数据。
